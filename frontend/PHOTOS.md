# Фото профілю

Повний перелік ендпоінтів і кодів відповіді — у `.claude/api.md`. Тут тільки те,
що стосується фронтенду.

## Головне

**Фронтенд не спілкується з Cloudinary.** Ніякого SDK, ніяких ключів, жодного
пакета встановлювати не треба.

```
браузер  ──файл──►  наш API  ──►  Cloudinary
браузер  ◄──URL───  наш API
браузер  ──────────────────────►  Cloudinary   (тільки коли <img> вантажить картинку)
```

Ключі Cloudinary лежать на сервері. У фронтенді їх бути не повинно ніколи:
код у браузері читає будь-хто, а `ApiSecret` дає повний доступ до сховища —
включно з видаленням чужих фото.

## Завантаження

`POST /api/profiles/me/photos`, `multipart/form-data`, поле називається `file`.

```ts
async function uploadPhoto(file: File): Promise<PhotoDto> {
  const form = new FormData();
  form.append("file", file);          // саме "file", інша назва дасть 400

  const { data } = await api.post<PhotoDto>("/api/profiles/me/photos", form);
  return data;
}
```

**Не став `Content-Type` вручну.** Ні в axios, ні у fetch. Браузер має
підставити його сам разом з `boundary`:

```
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryAbC123
```

`boundary` — випадковий роздільник між частинами тіла запиту. Якщо прописати
заголовок руками, він загубиться, і сервер не зможе розібрати запит.

```ts
// ❌ так зламається
headers: { "Content-Type": "multipart/form-data" }

// ✅ просто не чіпай
```

Заголовок `Authorization: Bearer <наш JWT>` потрібен, як і всюди.

### Відповідь `201 Created`

```json
{
  "id": "3f8a...",
  "url": "https://res.cloudinary.com/eedej0us/image/upload/v1725800000/echomatch/profiles/x7k2p.jpg",
  "isMain": true,
  "order": 0
}
```

Перше завантажене фото автоматично стає головним.

## Показ

URL готовий до вживання:

```tsx
<img src={photo.url} alt="" />
```

Проксі через бекенд не потрібне, авторизація для картинки не потрібна — файл
роздає CDN Cloudinary.

### Розміри під місце показу

Не тягни оригінал 1200×1200 у список мініатюр. Cloudinary вміє обробляти
картинку на льоту — параметри вставляються прямо в URL, одразу після
`/upload/`:

```
https://res.cloudinary.com/eedej0us/image/upload/v1725800000/echomatch/profiles/x7k2p.jpg
                                                ▲
                            сюди вставляємо f_auto,q_auto,w_400,h_400,c_fill
```

Хелпер:

```ts
export function cloudinaryUrl(url: string, transform: string): string {
  return url.replace("/upload/", `/upload/${transform}/`);
}
```

```tsx
<img src={cloudinaryUrl(photo.url, "f_auto,q_auto,w_400,h_400,c_fill,g_face")} />
```

Корисні параметри:

| Параметр | Що робить |
|---|---|
| `f_auto` | віддає WebP або AVIF, якщо браузер їх розуміє |
| `q_auto` | підбирає стиснення без видимої втрати якості |
| `w_400,h_400` | розмір у пікселях |
| `c_fill` | заповнити рамку, обрізавши зайве |
| `c_fit` | вписати цілком, не обрізаючи |
| `g_face` | при обрізанні тримати обличчя в кадрі |

`g_face` варто ставити скрізь, де фото обрізається — інакше на портреті
відріже голову.

Готові варіанти краще тримати в одному місці:

```ts
export const PHOTO = {
  thumb: "f_auto,q_auto,w_200,h_200,c_fill,g_face",
  card:  "f_auto,q_auto,w_600,h_800,c_fill,g_face",
  full:  "f_auto,q_auto,w_1200,c_limit",
} as const;
```

## Головне фото і видалення

```ts
// зробити головним
await api.put(`/api/profiles/me/photos/${photoId}/main`);

// видалити
await api.delete(`/api/profiles/me/photos/${photoId}`);
```

Обидва повертають `204` без тіла. Після них перечитай профіль — сервер міг
перенумерувати `order` і призначити нове головне фото.

Головне фото завжди рівно одне. Щоб знайти його в списку:

```ts
const main = profile.photos.find(p => p.isMain) ?? profile.photos[0];
```

## Обмеження і помилки

| Обмеження | Значення |
|---|---|
| Максимум фото | 9 на профіль |
| Розмір файлу | 5 МБ |
| Формати | JPEG, PNG, WebP, HEIC, HEIF |

| Код | Причина |
|---|---|
| `400` | завеликий файл, недозволений формат, порожній файл |
| `404` | профіль ще не створений, або фото не належить користувачу |
| `409` | уже 9 фото |

Текст для користувача бери з поля `detail` у відповіді — він українською:

```json
{ "title": "Validation error", "status": 400, "detail": "Максимальний розмір фото — 5 МБ." }
```

Перевіряй розмір і формат ще до відправки — не має сенсу вантажити 20 МБ,
щоб отримати `400`.

## Що врахувати про HEIC

Це типовий формат камери iPhone, і ми його приймаємо. Але **браузери HEIC не
відображають**.

Наслідок один: локальний прев'ю через `URL.createObjectURL(file)` для HEIC
покаже порожнє місце. Сервер конвертує файл у JPEG при завантаженні, тому `url`
з відповіді відкривається завжди.

Якщо потрібен прев'ю до відправки — або показуй заглушку з іменем файлу для
`.heic`, або взагалі не роби локальний прев'ю, а показуй картинку вже після
успішного завантаження.
